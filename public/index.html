The research model

A finding needs more than a convincing answer.

Research loses its meaning when a plan becomes proof, a URL becomes an endpoint, or a model’s confidence becomes permission. Ichnema keeps four records separate and linked.

  1. 01

    Knowledge

    Methods and procedures describe what could be investigated.

  2. 02

    Approved plan

    A pinned, human-approved plan defines bounded work, not a claim of completion.

  3. 03

    Recorded run

    Attempts and a hash-linked audit history show what actually happened.

  4. 04

    Evidence

    Hashed artifacts support observations. Conclusions still need validation.

Fail closed by default

The tool tells you what it cannot do.

Readiness is not a flag to flip. Until every hard gate has independent evidence, the core reports itself unready for live work and refuses to pretend otherwise.

  • Signed, expiring scope policy bound to the program brief
  • Leased, fenced tasks with evidence-hash receipts
  • No automatic replay of uncertain external actions

Roadmap

Build the authority before the autonomy.

The goal is a researcher-controlled workbench, not another place where an agent declares its own work done.

  1. Now · implemented

    The offline core

    A reproducible Python baseline, fixture execution, evidence integrity and installation tests. This is the present, not a live research service.

  2. Next · not implemented

    A versioned research library

    Drafts, immutable published revisions and reliable references. Methodologies are knowledge; they are not runnable workers.

  3. Later · planned

    One controller. A real workbench.

    Converged execution, a validated API and a web interface. Controlled AI and real adapters come only after their authorization, recovery and isolation gates.

A direction, not a release schedule. The autonomous hunting studio is not operational.

Boundaries

The limits are part of the design.

Clear boundaries are more useful than a bigger promise.

Can I use it for live hunting?

No. The core is offline-only. There is no live transport, independently proven OS egress containment, or operational autonomous hunting service. A fixture domain is never permission to test a target.

Is there an interactive Studio app?

Not yet. The current inspector is an escaped, static HTML export. The API, React workbench and visual workflow authoring remain planned work.

What can an AI agent authorize?

Nothing by itself. The target architecture lets agents analyze and propose. Independent authorization and the execution controller must decide what may run and what is complete. A live agent runtime is not implemented.

What is public on this site?

Only this project introduction and approved display assets. The development repository is private. No investigation data, evidence captures, credentials or original design files are published here.
